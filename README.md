# agent-bus

Шина сообщений между сессиями Claude Code и Codex. Поставляется плагином
Claude Code: MCP-сервер с каналом (channels), инструменты шины, хуки и навык
с протоколом.

Агент в одной сессии отправляет сообщение, а сессия напарника получает его
событием канала и просыпается сама, даже если ждала ввода. Сообщения
переживают закрытие сессии: недоставленное приходит при следующем старте.

Два режима:

- **Локальный.** Сессии на разных аккаунтах одной машины, журнал — файл
  в общем каталоге. Ничего, кроме плагина, не нужно.
- **Хаб.** Агенты на разных машинах, у разных людей, в том числе в Codex.
  Хаб — serverless-стек в AWS. Агенты делятся на команды, и писать можно
  только тиммейтам. Включается адресом хаба в настройках плагина, см.
  [docs/hub.md](docs/hub.md).

## Как это устроено

- **Хранилище — журнал событий JSONL.** В локальном режиме — общий каталог,
  по умолчанию `~/.agent-bus`. С хабом журнал ведёт хаб, а на машине лежит
  зеркало переписки агента, которое сервер дописывает по WebSocket. Статус сообщения хранится не полем, а отдельными
  событиями, поэтому журнал только дописывается. Запись идёт под `flock`.
- **Транспорт — сам журнал.** Сервер каждой сессии следит за его хвостом
  (или за зеркалом) и превращает новые сообщения для своего агента в
  события канала. Локально портов нет, доступ ограничен правами файловой
  системы. С хабом агент входит по своему токену, а отправителя хаб берёт
  из токена.
- **Участие включается явно.** В шину входит только сессия, запущенная с
  `AGENT_BUS_SESSION=1`. В остальных сессиях аккаунта сервер не объявляет
  инструментов, а хуки выходят сразу.
- **Хуки — подстраховка.** `SessionStart` сообщает о непрочитанном, `Stop`
  напоминает о необработанных сообщениях, `UserPromptSubmit` отмечает ходы
  человека. Фоновые (`async`) хуки сообщают, чем занята сессия: начало и
  конец хода, запрос разрешения, продолжение работы после него.
- **Состояние агентов.** `peers` показывает для каждого агента состояние
  (`working`, `idle`, `waiting_human`, `offline`) и с какого времени,
  время последнего отправленного сообщения и открытые задачи: `task` без
  ответа, с тредом и временем. «Ждёт человека» — это запрос разрешения или
  `await_human`, на который ещё не ответил человек. Codex хуков не имеет,
  поэтому он считается занятым, пока у него есть открытая задача.
- **Проверка на секреты.** Шина отказывается отправлять сообщение или
  вложение, похожее на ключ AWS, токен (GitHub, Slack, Anthropic, OpenAI,
  токен хаба, JWT, Bearer), приватный ключ, пароль в URL или строку `.env`
  с секретным именем. Отправитель получает правило и номер строки, но не
  сам фрагмент. Проверку выполняют и клиент, и хаб.
- **Вложения по хэшу.** Файлы передаются отдельно от сообщения, у каждого
  есть sha256. Получатель забирает их инструментом `attachments`, и тот
  отдаёт файл, только если хэш совпал. Файл хранится под своим хэшем, а не
  под именем, поэтому отправитель не выбирает, куда файл попадёт у
  получателя. Локально вложения лежат в `<bus_dir>/attachments/`, на хабе —
  в S3-бакете стека. До 10 файлов по 5 МБ на сообщение.
- **Защита от пинг-понга в коде.** На результат нельзя ответить ничем,
  кроме новой задачи, поэтому вежливые цепочки «спасибо — пожалуйста» не
  возникают. Страховка — не больше 30 сообщений между парой агентов за 5
  минут. Длинная работа по схеме «задача — результат — задача» не
  ограничена.

Подробный дизайн и решения — в [PLAN.md](PLAN.md).

## Установка и запуск

Хаб для агентов на разных машинах и подключение Codex описаны в
[docs/hub.md](docs/hub.md). Дальше — локальный режим.

Пошаговая инструкция для двух аккаунтов — в
[docs/bring-up.md](docs/bring-up.md). Коротко:

```bash
CLAUDE_CONFIG_DIR=<каталог аккаунта> claude plugin marketplace add ~/Projects/Personal/mcp-agent-bus
CLAUDE_CONFIG_DIR=<каталог аккаунта> claude plugin install agent-bus@agent-bus-dev
echo '{"agent_name": "<имя>"}' \
    | CLAUDE_CONFIG_DIR=<каталог аккаунта> claude plugin configure agent-bus@agent-bus-dev --values-stdin

CLAUDE_CONFIG_DIR=<каталог аккаунта> scripts/run.sh claude -- --model sonnet
```

`agent-bus claude` запускает `claude` с текущим окружением, включая
`CLAUDE_CONFIG_DIR`, и добавляет к нему `AGENT_BUS_SESSION=1`. Флаг канала
`--dangerously-load-development-channels plugin:agent-bus@agent-bus-dev` и
разрешение `--allowedTools mcp__plugin_agent-bus_bus` она тоже ставит сама.
Аргументы после `--` передаются `claude`. Вне репозитория команда
запускается через
`uvx --from git+https://github.com/AndrewKolpakov/mcp-agent-bus agent-bus claude`.

Чтобы запустить одну сессию под другим именем или на другом хабе, не меняя
настройки аккаунта, используйте `agent-bus --as <имя> --hub <адрес> claude`
(любой из флагов можно опустить). Обёртка задаст `AGENT_BUS_AS` и
`AGENT_BUS_VIA`, и они действуют и на сервер, и на хуки. `AGENT_BUS_NAME` и
`AGENT_BUS_HUB` для этого не подходят: блок `env` в манифесте задаёт их
серверу из `agent_name` и `hub_url` аккаунта, даже пустых, и значение из
оболочки дойдёт только до хуков.

## Командная строка

`scripts/run.sh` запускает CLI в собственном окружении плагина. В корне
репозитория можно также использовать `uv run agent-bus`.

| Команда | Что делает |
| :- | :- |
| `agent-bus tail -f` | Печатает журнал шины вживую |
| `agent-bus --as <имя> send --to <имя> "текст"` | Отправляет сообщение от имени агента |
| `agent-bus --as <имя> send --to <имя> -a <файл> "текст"` | Отправляет сообщение с вложением; `-a` можно повторить |
| `agent-bus --as <имя> inbox` | Показывает непрочитанное агента |
| `agent-bus --as <имя> history --from <имя> --thread <id> --since 2h -n 20` | Показывает отправленные и полученные сообщения с фильтрами; `--all` снимает ограничение |
| `agent-bus --as <имя> attachments <id>` | Забирает вложения сообщения и проверяет sha256 |
| `agent-bus --as <имя> ack <id>` | Отмечает сообщение обработанным |
| `agent-bus --as <имя> peers` | Показывает других агентов: на связи ли, чем заняты, последнее сообщение, открытые задачи |
| `agent-bus hub-token` | Сохраняет токен хаба со stdin в файл с правами 0600 |
| `agent-bus sync` | Догоняет зеркало хаба, когда сервер не запущен |
| `agent-bus claude` | Запускает сессию Claude Code на шине, с каналом |
| `agent-bus codex` | Запускает сессию Codex на шине |
| `agent-bus admin …` | Управляет агентами, токенами и командами хаба |

## agent-bus web

A local web page for a human who acts as a bus agent, with no AI involved:
`agent-bus --as owner web` (`--port` defaults to 8765; `--bus-dir` and `--hub`
apply as for every command). It prints `http://127.0.0.1:<port>/`; open it in a
browser. The server listens on 127.0.0.1 only.

- The page shows the messages addressed to you, unread first, and polls every 5 seconds
  (on a hub it syncs first).
- Each message that can be answered has a text box and a kind choice; a message of
  kind `result` or `await_human` can only be acked.
- A "New message to personal" box sends a new text message.
- Nothing is acked on its own: a message is acked only by answering it or by the
  "Ack shown" button.
- Sending goes through the same checks as the CLI: secret scan, reply rules, rate limit.

## Разработка

```bash
uv sync
uv run ruff check
uv run ruff format --check
uv run mypy
uv run pytest
claude plugin validate .
claude plugin validate .claude-plugin/plugin.json
```

Тесты хаба идут против moto. Сквозной тест двух сессий через развёрнутый хаб
запускается отдельно и создаёт временных агентов:

```bash
AWS_PROFILE=<профиль> AWS_REGION=<регион> AGENT_BUS_TEST_HUB_STACK=<стек> \
    uv run pytest tests/integration/test_hub_e2e.py
```

## Известные ограничения

- **Каналы в research preview.** Свой плагин грузится только флагом
  `--dangerously-load-development-channels`, а флаги и контракт канала могут
  измениться.
- **Одна доставляющая сессия на агента.** Вторая сессия того же агента на
  шине работает без канала и читает входящие через `inbox`. Канал она
  подхватывает, когда первая закрывается или глохнет.
- **Фоновые сессии не получают событий.** Ни запущенная с `--bg`, ни
  переведённая в фон. Доставка подтверждается по транскрипту сессии, и
  сессия, куда событие не дошло за 120 секунд, отдаёт канал. До этого
  сообщение ждёт, а в фоне о нём сообщают хуки. Доставкой считается
  извлечение события из входной очереди сессии, а не постановка в неё:
  процесс, чей разговор ушёл в фон, ставит событие в очередь, но больше
  ничего не пишет. Транскрипт — внутренний формат Claude Code. Если в
  ожидаемом месте нет ни одного транскрипта, сервер по истечении срока
  считает отправленное доставленным, как без подтверждения.
- **Длинный ход выглядит как глухота.** Занятая сессия записывает событие
  в транскрипт только в конце текущего хода. Если ход длится дольше 120
  секунд, сессия временно отдаёт канал и возвращает его при подтверждении.
  Если в это время на шине есть вторая сессия того же агента, она подхватит
  канал и получит то же сообщение повторно. Для агентов с долгими задачами
  поднимите `AGENT_BUS_CONFIRM_SECONDS` и не держите на шине вторую сессию
  того же агента.
- **Нет ротации журнала.** Если журнал усечь, наблюдатель работающей сессии
  останется на старом смещении, пока сессию не перезапустят.
- **Codex получает сообщения ходами через `codex queue`.** Новый разговор
  в Codex получает их только после первого вызова инструмента шины, а
  такой ход выглядит в Codex как ход пользователя.
- **Модель не слабее Sonnet.** Haiku видит событие, но не выполняет
  инструкцию ответить.
- **Навык виден во всех сессиях аккаунта.** Без `AGENT_BUS_SESSION=1` хуки
  и сервер молчат, но описание навыка всё равно попадает в список навыков.
