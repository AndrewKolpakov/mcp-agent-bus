# agent-bus

Шина сообщений между сессиями Claude Code на разных аккаунтах одной машины.
Поставляется плагином Claude Code: MCP-сервер с каналом (channels),
инструменты шины, хуки и навык с протоколом.

Агент в одной сессии отправляет сообщение, а сессия напарника получает его
событием канала и просыпается сама, даже если ждала ввода. Сообщения
переживают закрытие сессии: недоставленное приходит при следующем старте.

## Как это устроено

- **Хранилище — журнал событий JSONL** в общем каталоге, по умолчанию
  `~/.agent-bus`. Статус сообщения хранится не полем, а отдельными
  событиями, поэтому журнал только дописывается. Запись идёт под `flock`.
- **Транспорт — сам журнал.** Сервер каждой сессии следит за его хвостом и
  превращает новые сообщения для своего агента в события канала. Портов нет,
  доступ ограничен правами файловой системы.
- **Участие включается явно.** В шину входит только сессия, запущенная с
  `AGENT_BUS_SESSION=1`. В остальных сессиях аккаунта сервер не объявляет
  инструментов, а хуки выходят сразу.
- **Хуки — подстраховка.** `SessionStart` сообщает о непрочитанном, `Stop`
  напоминает о необработанных сообщениях, `UserPromptSubmit` отмечает ходы
  человека.
- **Защита от пинг-понга в коде.** Два агента могут обменяться ограниченным
  числом сообщений, пока человек не заговорит снова.

Подробный дизайн и решения — в [PLAN.md](PLAN.md).

## Установка и запуск

Пошаговая инструкция для двух аккаунтов — в
[docs/bring-up.md](docs/bring-up.md). Коротко:

```bash
CLAUDE_CONFIG_DIR=<каталог аккаунта> claude plugin marketplace add ~/Projects/Personal/mcp-agent-bus
CLAUDE_CONFIG_DIR=<каталог аккаунта> claude plugin install agent-bus@agent-bus-dev
echo '{"agent_name": "<имя>"}' \
    | CLAUDE_CONFIG_DIR=<каталог аккаунта> claude plugin configure agent-bus@agent-bus-dev --values-stdin

AGENT_BUS_SESSION=1 CLAUDE_CONFIG_DIR=<каталог аккаунта> claude --model sonnet \
    --allowedTools mcp__plugin_agent-bus_bus \
    --dangerously-load-development-channels plugin:agent-bus@agent-bus-dev
```

## Командная строка

`scripts/run.sh` запускает CLI в собственном окружении плагина. В корне
репозитория можно также использовать `uv run agent-bus`.

| Команда | Что делает |
| :- | :- |
| `agent-bus tail -f` | Печатает журнал шины вживую |
| `agent-bus --as <имя> send --to <имя> "текст"` | Отправляет сообщение от имени агента |
| `agent-bus --as <имя> inbox` | Показывает непрочитанное агента |
| `agent-bus --as <имя> ack <id>` | Отмечает сообщение обработанным |
| `agent-bus --as <имя> peers` | Показывает других агентов и их сессии |

## Известные ограничения

- **Каналы в research preview.** Свой плагин грузится только флагом
  `--dangerously-load-development-channels`, а флаги и контракт канала могут
  измениться.
- **Одна доставляющая сессия на агента.** Вторая сессия того же агента на
  шине работает без канала и читает входящие через `inbox`.
- **Нет ротации журнала.** Если журнал усечь, наблюдатель работающей сессии
  останется на старом смещении, пока сессию не перезапустят.
- **Модель не слабее Sonnet.** Haiku видит событие, но не выполняет
  инструкцию ответить.
- **Навык виден во всех сессиях аккаунта.** Без `AGENT_BUS_SESSION=1` хуки
  и сервер молчат, но описание навыка всё равно попадает в список навыков.
