# Хаб: шина между машинами

Хаб соединяет агентов на разных машинах (PLAN.md, v2). Это serverless-стек в
AWS: API Gateway (HTTP и WebSocket), одна Lambda и одна таблица DynamoDB.
Постоянно ничего не работает, оплата идёт за события. При нескольких
агентах и сотнях сообщений в день это центы в месяц. Без хаба шина
остаётся локальной.

Роли:

- **Владелец хаба** разворачивает стек и выдаёт агентам токены и команды.
  Ему нужны AWS-права на стек и таблицу.
- **Владелец агента** получает от владельца хаба блок с адресом и токеном
  и подключает свою сессию Claude Code или Codex. AWS ему не нужен.

Агент видит только свою переписку и пишет только тиммейтам. Отправителя хаб
берёт из токена, защиту от петель проверяет сам.

## Развернуть хаб

Нужны `uv`, [AWS SAM CLI](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/install-sam-cli.html),
AWS-права на CloudFormation, Lambda, API Gateway, DynamoDB, IAM-роли
стека и CloudWatch Logs, а также S3-бакет для артефактов. Стек пишет
журналы доступа WebSocket API, а для этого в регионе должна быть задана
CloudWatch-роль API Gateway на уровне аккаунта (`Settings` в консоли API
Gateway). Шаблон её не создаёт и не меняет.

```bash
export AWS_PROFILE=<профиль> AWS_REGION=<регион>
hub/build.sh
sam deploy --template-file hub/template.yaml --stack-name <стек> \
    --parameter-overrides Name=<стек> \
    --s3-bucket <бакет для артефактов> --s3-prefix <стек> \
    --capabilities CAPABILITY_IAM
```

- **`hub/build.sh`** собирает пакет лямбды для arm64 и Python 3.12 без
  Docker: колёса manylinux ставит `uv`.
- **`Name`** задаёт имя таблицы и журналов, по умолчанию `agent-bus-dev`.
  Другие параметры: `RateLimit` и `RateWindowSeconds` (защита от петель,
  по умолчанию 30 сообщений за 300 с на пару агентов) и
  `LogRetentionDays` (14).
- **Выходы стека:** `HttpUrl` — адрес хаба для агентов, `WsUrl`,
  `TableName`.

Проверка развёрнутого хаба. Smoke создаёт временных агентов, проверяет
доставку, отказы и неверный токен, затем отзывает их токены:

```bash
uv run --with websockets --with 'botocore[crt]' python hub/smoke.py <стек>
```

Удалить хаб можно командой `sam delete --stack-name <стек>`. Вместе со
стеком удаляется таблица со всей перепиской.

## Выдать доступ

`agent-bus admin` пишет таблицу хаба напрямую, с AWS-правами владельца, так
что у API хаба нет админских маршрутов. Стек задаётся через `--stack` или
`AGENT_BUS_ADMIN_STACK`. В репозитории команда работает через `uv run`, вне
его нужен пакет с extra `admin` (`boto3`).

```bash
export AWS_PROFILE=<профиль> AWS_REGION=<регион> AGENT_BUS_ADMIN_STACK=<стек>
uv run agent-bus admin agent add <агент> --team <команда>
```

| Команда | Что делает |
| :- | :- |
| `agent add <агент> [--team T]` | Создаёт агента и печатает блок для его владельца |
| `agent list`, `team list` | Агенты с их командами, команды с участниками |
| `member add\|remove <команда> <агент…>` | Меняет состав команды |
| `token rotate <агент>` | Выдаёт новый токен и печатает блок заново |
| `token revoke <агент>` | Оставляет агента без токена |
| `agent remove <агент> --yes` | Удаляет агента, его токен, членство и переписку |
| `tail [-n N] [-f] [--json]` | Весь журнал хаба, по всем агентам |

Старый токен после `rotate` или `revoke` перестаёт работать на WebSocket
сразу, а по HTTP — в течение 60 секунд: столько авторизатор кэширует
ответ.

### Что выдаёт администратор хаба

`agent add` и `token rotate` печатают всё нужное одним блоком: адрес хаба,
имя агента, токен и команду, которая сохраняет токен на машине агента.
Блок передаётся владельцу агента по закрытому каналу. В нём есть:

- **Адрес хаба:** `https://….execute-api.<регион>.amazonaws.com`.
- **Имя агента.** Оно задано на хабе, и `agent_name` плагина должен
  совпадать с ним.
- **Токен `ab_…`.** Его показывают один раз, на хабе хранится только хеш.

Писать агент может только участникам своих команд.

## Подключить Claude Code

Плагин ставится из GitHub. Для локальной шины на одной машине — см.
[bring-up.md](bring-up.md).

```bash
claude plugin marketplace add https://github.com/AndrewKolpakov/mcp-agent-bus
claude plugin install agent-bus@agent-bus-dev
```

1. Укажите в настройках плагина `agent_name` и адрес хаба `hub_url`. В
   окружении адрес можно задать и через `AGENT_BUS_HUB`.

   ```bash
   claude plugin configure agent-bus
   ```

2. Сохраните токен на машине агента командой из блока администратора.
   Копия репозитория для этого не нужна. Команда читает токен со stdin
   (вставьте его и нажмите Ctrl-D), чтобы он не попал в историю shell и в
   список процессов, и кладёт его в файл с правами 0600:

   ```bash
   AGENT_BUS_HUB=<адрес> AGENT_BUS_NAME=<агент> \
     uvx --from git+https://github.com/AndrewKolpakov/mcp-agent-bus agent-bus hub-token
   ```

   Файл лежит в `~/.agent-bus/hubs/<хост хаба>/<агент>/token`. Токен
   нельзя хранить в `userConfig`: опции плагина попадают в окружение
   каждого хука. Если файл читается кем-то, кроме вас, сервер откажется
   его использовать.

3. Запустите сессию через обёртку. Она сохраняет текущее окружение,
   включая `CLAUDE_CONFIG_DIR`, и добавляет `AGENT_BUS_SESSION=1`, флаг
   канала и разрешение на инструменты шины:

   ```bash
   uvx --from git+https://github.com/AndrewKolpakov/mcp-agent-bus agent-bus claude
   ```

   Аргументы для `claude` идут после `--`. Без обёртки сессию запускают с
   `AGENT_BUS_SESSION=1` и
   `--dangerously-load-development-channels plugin:agent-bus@agent-bus-dev`.
   Без флага канала сессия на шине, но события к ней не приходят.

## Подключить Codex

У Codex нет каналов Claude Code, но простаивающую сессию можно разбудить:
`codex queue --thread <id>` запускает в ней ход, а занятой сессии ставит
ход в очередь. Этим пользуется обёртка `agent-bus codex`:

1. Сохраните токен, как в шаге 2 выше.
2. Запускайте Codex через обёртку:

   ```bash
   AGENT_BUS_HUB=<адрес> AGENT_BUS_NAME=<агент> \
     uvx --from git+https://github.com/AndrewKolpakov/mcp-agent-bus agent-bus codex
   ```

   Аргументы для самого Codex идут после `--`, например
   `agent-bus codex -- -m <модель>`.

Что делает обёртка:

- **Подключает сервер шины только к этой сессии** через `-c`. В
  `~/.codex/config.toml` ничего добавлять не нужно. Обычный `codex` и
  `codex exec`, запущенный из сессии на шине, шину не видят.
- **Запускает Codex с `--no-daemon`.** Иначе сессией управляет общий
  фоновый сервер Codex.
- **Открывает сессию просьбой вызвать `peers`.** Codex сообщает id сессии в
  `_meta` каждого вызова инструмента, и до первого вызова серверу некуда
  доставлять. После него сервер передаёт накопившиеся сообщения и дальше
  доставляет каждое новое через `codex queue`. Сообщение приходит ходом,
  который начинается с `<agent-bus-message from=… kind=… msg_id=…>`.

Сервер держит канал, как сессия Claude Code, поэтому для других агентов
`codex` в `peers` live. Если начать в Codex новый разговор, сообщения идут в
прежний, пока новый не вызовет любой инструмент шины.

Для клиента, которого разбудить нельзя, есть `AGENT_BUS_CHANNEL=0`. Сервер
тогда ничего не доставляет, а модель читает сообщения сама: `inbox`, при
необходимости с `wait_seconds` (до 300 с).

## Как это работает на машине

- **Зеркало.** Сервер держит WebSocket к хабу и дописывает своё
  представление в `~/.agent-bus/hubs/<хост>/<агент>/log.jsonl`. Хуки и
  `agent-bus inbox` читают этот файл и в сеть не ходят. `agent-bus sync`
  догоняет зеркало вручную, когда сервер не запущен.
- **Проверка токена.** При старте сервер спрашивает хаб, чей это токен.
  Если токен принадлежит другому агенту, сессия остаётся вне шины и
  объясняет причину в инструкциях.
- **Хаб недоступен.** Чтение работает по зеркалу, отправка возвращает
  ошибку. Сервер переподключается сам.
